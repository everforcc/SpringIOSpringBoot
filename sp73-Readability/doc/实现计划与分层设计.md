# sp73-Readability 实现计划与分层设计

面向《通用小说爬虫系统设计方案》的落地路线，按分层解耦实现。

## 分层与职责
- Web/API 层：后续提供手工触发/状态查询接口（可选）。
- Scheduler 层：基于 `@Scheduled` 周期性触发目录拉取、队列巡检、失败重试。
- Service 层：
  - `TaskQueueService`：Redis 任务队列、去重与限速（List/Set/Hash）。
  - `CatalogParser`：目录页解析（Jsoup + 启发式章节容器识别）。
  - `ReadabilityService`：章节页正文提取（Readability 清洗评分）。
  - `ChapterPersistenceService`：MySQL 持久化（Novel/Chapter）。
- Integration 层：HTTP 抓取（OkHttp/RestTemplate）、Redis、MyBatis。
- Domain 模型：已存在 `Novel`、`Chapter`、`ChapterTask`、`ChapterLink`、`CatalogPageResult`、`ReadabilityResult`。

## 迭代计划（建议顺序）
1) 基础设施
   - 补充 Redis/MySQL 配置与连接测试。
   - 实现 `TaskQueueService`（RedisTemplate），包含去重、队列操作、URL 哈希工具。
   - 补充 DDL（`doc/ddl/novel_chapter.sql`）并导入。
2) 目录解析链路
   - 实现 `CatalogParser`：Jsoup 解析，启发式寻找章节链接容器，生成 `CatalogPageResult`。
   - 将章节链接推入 `TaskQueueService.pushChapterTask`，写入 aiReadabilityNovel 元数据。
3) 章节抓取链路
   - HTTP 抓取章节页，限速（域名 last-visit + sleep），失败重试。
   - `ReadabilityService.parse` 提取正文与标题。
   - 持久化章节，探测下一章链接并回推队列。
4) 调度与接口
   - 定时任务：目录补偿、章节队列消费、失败重试。
   - 简单管理接口：触发目录抓取、查看队列长度/运行状态。
5) 监控与优化（可选）
   - 抓取/解析成功率、延迟、队列堆积监控。
   - 代理池、UA 轮换、指数退避重试策略。

## 数据与 Key 约定
- MySQL：`aiReadabilityNovel`、`aiReadabilityChapter` 表，字符集 `utf8mb4`，内容字段用 `LONGTEXT`。
- Redis Key：见 `constants.RedisKeys`（队列、去重、限速、元数据缓存）。
