# sp73-Readability 实现计划与分层设计

## 总体分层
- 接口层（可选）：后续可提供简单的 HTTP 入口用于触发爬取或查看状态。
- 调度层：定时任务/worker 启动入口，轮询 Redis 队列，执行目录/章节抓取。
- 队列与去重层：`TaskQueueService`（Redis）负责目录、章节队列和 URL 去重。
- 解析层：`CatalogParser` 负责目录页解析（元数据 + 章节链接）；`ReadabilityService` 负责章节页正文提取。
- 持久化层：`ChapterPersistenceService` 负责写入 MySQL（aiReadabilityNovel/aiReadabilityChapter 表）。
- 限速与容错：基于 Redis Hash 记录域名访问时间、指数退避重试、失败回退队列。

## 近期落地任务拆分
1) DDL 准备：提交 `ddl/schema.sql`，包含 `aiReadabilityNovel` 与 `aiReadabilityChapter` 表。
2) Redis 交互实现：基于 Spring Data Redis 实现 `TaskQueueService`，封装队列/Set/Hash。
3) 目录解析实现：用 Jsoup 编写启发式目录页解析（相似链接容器识别、相对 URL 补全），返回 `CatalogPageResult`。
4) 章节解析实现：实现 Readability 清洗与正文抽取，返回 `ReadabilityResult`，含章节标题回填。
5) 持久化实现：MyBatis 映射与 DAO，落地小说与章节写入；必要的唯一索引/幂等处理。
6) Worker 流程：编排目录->章节链路，串起限速、去重、重试。
7) 观测与测试：增加少量集成/冒烟测试（可选），并在流水文档记录每次改动。

## 注意点
- 去重：对 URL 进行标准化/哈希后写入 `aiReadabilityNovel:url:crawled`。
- 限速：`aiReadabilityNovel:rate_limit` 按域名存上次时间戳；请求前检查、请求后更新。
- 失败回退：抓取异常时将任务信息写回队列或落日志，避免丢任务。
- 字符集与时区：保持 JDBC URL 中的字符集/时区参数一致。
