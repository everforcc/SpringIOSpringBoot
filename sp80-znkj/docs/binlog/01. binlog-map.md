## Binlog Map 方案使用说明

### 1. 背景概述
该方案通过 `mysql-binlog-connector-java` 直接订阅 MySQL Binlog，使用内存 `Map` 作为临时通道，再结合 MyBatis 持久化，实现 “捕获 → SQL 转换 → 缓存 → 落库 → 恢复” 的闭环，适用于本地验证和单机 PoC。

### 2. 关键组件调用关系
```
MySQL Binlog
     │
     ▼ (BinaryLogClient Event)
BinlogConnectorListener ──➤ BinlogPositionTracker
     │
     ▼
BinlogEventProcessor
     ├─ TableMetadataCache（按 tableId 缓存列信息）
     ├─ SQLBuilderService（构造 INSERT/UPDATE/DELETE/QUERY SQL）
     ▼
BinlogMessageSender
     ├─ BinlogMessageBuffer(Map，按 database.table 聚合)
     └─ MessageStorageService
          └─ BinlogMessageMapper(MyBatis) → binlog_message 表
```
> Map 缓存用于近实时消费或调试；DB 记录用于断点恢复、回放校验。

### 3. 快速使用步骤
1. **配置 MySQL 连接与位点**  
   在 `application.yml` 中新增：
```yaml
binlog:
  mysql:
    host: 127.0.0.1
    port: 3306
    username: root
    password: xxx
    server-id: 1338        # 确保在 MySQL 主库中唯一
    binlog-filename: mysql-bin.000001
    binlog-position: 4
```
2. **准备元数据库权限**  
   监控账号需具备 `REPLICATION SLAVE`, `REPLICATION CLIENT`, 以及读取 `information_schema.COLUMNS` 的权限，用于 `TableMetadataCache` 懒加载列信息。

3. **初始化持久化表**  
   根据 `BinlogMessageMapper.xml` 建表，字段需包含：
   - `database_name`, `table_name`, `sql_type`, `sql_list_json`
   - `binlog_file`, `binlog_pos`, `event_time`, `created_at`

4. **启动 Spring Boot 应用**  
   - `BinlogConnectorListener` 在容器启动后自动连接 MySQL。
   - 事件通过 `BinlogEventProcessor → BinlogMessageSender` 写入 Map 和 DB。

5. **读取 & 恢复**  
   - 近实时处理：调用 `BinlogMessageBuffer.drainMessages(key)` 获取某个 `database.table` 的最新 SQL 集合。
   - 历史回放：使用 `MessageStorageService.loadMessages(...)` 按时间段加载 SQL，再依次执行实现恢复。

### 4. 常见问题
| 问题 | 排查建议 |
| --- | --- |
| 收不到事件 | 检查 serverId 是否唯一、MySQL 是否开启 binlog、网络 ACL。 |
| SQL 缺少列 | 确认监听账号能访问 `information_schema.COLUMNS`，并确保目标表未被频繁 DDL。 |
| Map 内存增长 | 调整 `BinlogMessageBuffer` 的 `maxSizePerKey`，或消费后立刻 `drainMessages`。 |

### 5. 后续演进
当验证完成后，可将 `BinlogMessageSender` 替换为 MQ Producer，把 `BinlogMessageBuffer` 切换为 MQ Consumer/Listener，其余 SQL 构建与持久化流程无需改动。***
